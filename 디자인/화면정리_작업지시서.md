## 0. 배경 (먼저 읽기)

- **Callog(콜록)**: 혼자 사는 어르신이 하루 한 번 짧은 질문과 말하기로 안부를 남기면, 이상 신호가 있을 때 가족(보호자)에게 알려 주는 웹앱(PWA)입니다.
  - 어르신 화면: `/elder/*`, 스타일 `src/styles/elder.css`
  - 보호자 화면: `/guardian/*`, 스타일 `src/styles/guardian.css`
  - 공통 토큰: `src/styles/theme.css`
  - 코드 위치: `demo/v1/` (React 19 + Vite + TypeScript, Supabase)
- **왜 고치나**: AX-Ton 기술 멘토링 3회차(2026-11-19)에서 "화면에서 AI로 만든 티가 난다"는 지적을 받았습니다. 구체적으로는 이렇습니다.
  - 도형이 크고 간격이 좁음
  - 글씨체와 목록 모양이 화면마다 다름
  - 화면 크기가 넘어갈 때마다 달라짐
- **멘토 제안(2순위 "화면 정리")**
  - 글씨체 하나로 통일
  - 목록 모양 통일, 안내 문구는 한 줄로
  - 도형 사이와 글자 주변에 여백 넣기
  - AI 이미지와 장식 줄은 다른 것으로 교체
  - 화면 크기가 넘어가도 같게
  - "시작하기" 버튼이 꼭 필요한지 다시 보기
  - 마음에 드는 앱 화면과 비교해 규칙으로 저장
  - 고친 내용은 기록해 두고 다음 화면에 그대로 적용
- **방법(디자인 짜깁기)**: Callog와 어울리는 앱들을 조사해 **장점만** 골랐고, 그 결과를 `DESIGN.md`에 규칙으로 적었습니다(2장). 이 지시서는 그 규칙을 코드에 옮기는 순서입니다.

## 1. 지켜야 할 것

1. **로직·데이터·라우팅·API는 건드리지 않습니다.** 스타일(CSS), 마크업 구조(JSX), 화면 문구만 바꿉니다.
2. 색은 `theme.css`·`elder.css`의 토큰만 씁니다. 바탕 테마 4종(어르신: 밤하늘·한낮·노을·또렷하게 / 보호자: 다크·라이트·노을·또렷하게)이 모두 계속 읽혀야 합니다.
3. 접근성은 그대로 유지합니다.
   - 누르는 곳 44px 이상, 어르신 주요 버튼 높이 60px 이상
   - "글씨 크게"(1 / 1.15 / 1.3배)에서 넘치지 않을 것
   - `prefers-reduced-motion`, `aria-*`, 화면 낭독기 문구
4. 법적 고지(녹화 동의, 의료 면책, 약관)는 **지우지 않습니다.** 한 줄로 줄이고 나머지는 "자세히"로 접습니다. 약관·개인정보 화면(`terms.tsx`)의 문장은 바꾸지 않습니다.
5. 한 단계 = 한 커밋. 커밋 메시지는 이 저장소의 기존 형식(한국어로 "무엇을 하게 한다/고친다")을 따릅니다.
6. 단계가 끝날 때마다 `DESIGN.md` 맨 아래 "고친 기록"에 한 줄 추가합니다.
7. 8단계 항목은 사람이 정할 일입니다. 묻고 기다립니다.

## 2. 짜깁기 근거: 어떤 앱에서 무엇을 가져왔나

고른 기준은 네 가지입니다.
- 어르신이 실제로 많이 쓰거나 익숙한가
- 같은 일(혼자 사는 분 매일 확인)을 하는가
- 어르신용 단순화의 표준인가
- 한국어 화면 규칙이 공개돼 있는가

## 3. 작업 단계

각 단계마다 **할 일 → 파일 → 완료 기준 → 확인**을 적었습니다.

### 0단계: 규칙 문서 자리 잡기

- 할 일
  - 받은 `DESIGN.md`를 저장소 맨 위(`HELPO-Callog/DESIGN.md`)에 둡니다.
  - 이 지시서와 대응표는 `디자인/` 폴더에 둡니다.
  - (선택) 참고 원본을 받습니다:

    ```bash
    npx getdesign@latest add notion --out design-refs/notion.md
    npx getdesign@latest add airbnb --out design-refs/airbnb.md
    ```

    사람이 고른 앱 캡처가 있으면 `design-refs/screens/`에 둡니다.
- 완료 기준: 이후 모든 단계에서 `DESIGN.md`를 먼저 읽고 시작함.

### 1단계: 글씨를 한 체계로 (토스 위계 · getdesign 단계)

- 할 일
  - `font-size`를 어르신 5단계(28·22·19·17·15), 보호자 5단계(26·20·17·15·13)로 맞춥니다.
  - `font-weight: 800`은 700으로 바꿉니다.
  - 값마다 역할을 보고 정합니다. 대응표의 "바꿀 값"은 기계적으로 가장 가까운 값이라, **역할이 다르면 역할을 따릅니다**(예: 카드 제목이면 소제목 단계).
- 파일: `elder.css`(26곳), `guardian.css`·`theme.css`(39곳), 인라인 `style={{ fontSize }}`가 있는 TSX
- 완료 기준: 아래 명령 결과에 5단계 밖의 값이 없음(40px 이상 그림 글자 예외).

  ```bash
  grep -ohE "font-size: *calc\(([0-9.]+)px" src/styles/elder.css | grep -oE "[0-9.]+" | sort -nu
  grep -ohE "font-size: *calc\(([0-9.]+)px" src/styles/guardian.css src/styles/theme.css | grep -oE "[0-9.]+" | sort -nu
  grep -c "font-weight: 800" src/styles/*.css   # 모두 0
  ```

### 2단계: 여백을 한 체계로 (getdesign 4px 단위 · Notion "묶음은 빈칸으로")

- 할 일
  - `margin`·`padding`·`gap`을 4·8·12·16·24·32·48·64로 맞춥니다.
  - 원칙: **같은 묶음 안은 좁게(8~12), 묶음 사이는 넓게(24~32)**.
  - 어르신 처음 화면의 "안부 시작하기"와 "119에 직접 전화하기" 사이 가로줄은 빼고 32px 빈칸으로 둡니다.
- 파일: `elder.css`(66곳), `guardian.css`·`theme.css`(57곳), 인라인 `style={{ margin…, padding…, gap }}` 37곳(`reg.tsx` 12, `gDetail.tsx` 9 등)
- 완료 기준: 위 8개 밖의 px 값이 없음(1~3px 테두리·미세 조정 예외). 인라인 여백은 가능하면 클래스로 옮깁니다.

### 3단계: 컴포넌트 5종 + 어르신 화면 고정 자리 (토스 일관성 · 카카오톡 목록 · Apple 손쉬운 사용 모드)

- 할 일
  1. **버튼 4종**: 주요·보조·위급·글자 버튼. 같은 종류는 어느 화면에서나 같은 모양입니다.
     - 보호자 시작 화면은 "구글로 계속하기"만 주요 버튼으로 둡니다. "이메일로 계정 만들기"·"이메일로 로그인"은 보조나 글자 버튼으로 낮춥니다.
  2. **선택지** 하나로 통일: `e-choice` `e-opt-row` `g-opt-row` `g-chip`이 같은 모서리·선·선택 상태를 씁니다.
  3. **행 목록**(카카오톡처럼 상자 없이 한 줄씩 + 1px 구분선)
     - 대상자 목록 `g-list-item`, 동의 행 `g-consent-row`, 영상편지 목록
     - 사용 안내(`guide.tsx`)의 '파란 동그라미 번호 + 상자 4개'와 '1. 2.' 숫자 목록을 **하나의 번호 행 목록**으로
  4. **카드** 하나로: `e-card` `g-card` `gd-card` `e-fortune-slip` `g-stat`. 카드 안에 카드 금지.
  5. **배지** 하나로: `g-today-badge` `e-badge-new` `RiskDot`
  6. **어르신 화면 고정 자리**(Apple 손쉬운 사용 모드의 "항상 같은 자리")
     - 상단 바 한 줄: 왼쪽 "이전"(글자 버튼), 오른쪽 "화면 설정"(글자 버튼). 지금 `eCheck.tsx`는 "이전" 버튼과 `e-topbar`가 따로 두 줄입니다(202~206행 부근). 로고 "Callog"는 처음 화면에만 둡니다.
     - "읽어주기"(`SpeakButton`)는 항상 화면 제목 바로 아래 왼쪽에 둡니다. 지금 `eSpeech.tsx`는 상단 바 안(133행), 다른 화면은 제목 아래로 제각각입니다.
     - 주요 행동 버튼은 항상 내용 맨 아래에 둡니다.
  7. 보호자 화면의 떠 있는 "가+ 화면 설정" 버튼이 카드 모서리와 "회원 탈퇴" 버튼을 가립니다. 상단 바 안으로 넣습니다.
- 파일: `elder.css`, `guardian.css`, `eHome.tsx` `eCheck.tsx` `eSpeech.tsx` `eDone.tsx` `gStart.tsx` `gList.tsx` `guide.tsx` `cond.tsx` `signup.tsx`, `components/DisplaySettings.tsx`, `components/RiskDot.tsx`
- 완료 기준
  - 위 클래스들이 5종의 공통 클래스(또는 공통 규칙)로 모임
  - 어르신 네 화면(처음·질문·말하기·완료)에서 "이전"·"화면 설정"·"읽어주기" 자리가 같음

### 4단계: 글 (토스 해요체·잡초 뽑기·버튼 문구 · Snug 밝은 말투)

- 할 일
  1. **앱 전체 해요체.** 지금 화면 문구에 "~니다"가 153곳, "~요"가 106곳으로 섞여 있습니다. 약관·개인정보(`terms.tsx`)만 빼고 해요체로 바꿉니다.
     - 많은 곳: `guide.tsx` 33, `gDetail.tsx` 14, `gList.tsx` 11, `cond.tsx` 10, `signup.tsx` 9, `reg.tsx` 6, `reset.tsx` 6
     - 오류 메시지 문자열(`setError("…")`)도 포함합니다.
  2. **안내는 화면마다 한 줄.** 제안 문장(최종은 사람 확인):

     | 화면 | 지금 | 제안 |
     |---|---|---|
     | 말하기 `RecordingNotice` | 본인의 음성/모습만 녹화해 주세요. 타인의 동의 없는 촬영은 법적 책임을 질 수 있습니다. | 본인 목소리만 녹음해 주세요 (+ 자세히) |
     | 보호자 목록 `MedicalDisclaimer` | 본 서비스는 의료기기나 의료 진단 서비스가 아니며, … (3줄) | 의료 진단이 아니라 안부 확인용 신호예요 (+ 자세히) |
     | 지병 선택 | 고른 병에 따라 질문이 달라지고, 같은 대답의 무게도 달라집니다. | 고른 병에 맞춰 질문이 바뀌어요 |
     | 시작 화면 | 어르신을 등록하고 초대하면, 어르신은 링크만 한 번 누르면 됩니다. | 어르신은 링크만 누르면 돼요 |
     | 사용 안내 첫 문단 | 2줄 | 하루 한 번 안부를 여쭙고, 이상하면 가족에게 알려요 |

  3. **버튼 문구는 누르면 생기는 일로.** 예: "다음 — 어르신 정보" → "어르신 정보 입력하기". "확인"·"완료"·"저장"만 있는 버튼을 찾아 바꿉니다.
  4. **말투는 밝고 긍정적으로**(Snug). 위험 알림 문구는 겁주지 않고 할 일을 먼저 말합니다.
  5. **오타 수정**: `src/lib/topics.ts` 18행 "어젯밤에는 잘 주셨어요?" → "어젯밤에는 잘 주무셨어요?"
- 완료 기준
  - `grep -rhoE '[가-힣]+니다' --include=*.tsx src/screens src/components src/features | grep -v terms` 결과가 법적 문장 몇 개만 남음
  - 안내 문단이 화면마다 한 문장

### 5단계: 장식 줄·이모지·생성 이미지 걷어내기 (토스 "색과 장식은 최소한")

| 무엇 | 위치 | 바꾸기 |
|---|---|---|
| 운세 쪽지 왼쪽 4px 금색 줄 | `elder.css` `.e-fortune-slip { border-left }` (393행 부근) | 삭제. 쪽지 제목이 이미 구분함 |
| 통계 칸 왼쪽 3px 색 줄 | `guardian.css` `.g-stat::before` (439행 부근) | 삭제. 상태는 숫자 색이나 배지로 |
| 로고 앞 네모 점 | `guardian.css` `.g-brand::before` (254행 부근) | 삭제 |
| 안내 글 속 이모지 | `guide.tsx` 124행 "🔕 위험 알림 받기" 등 | 글자만 |
| 앱 아이콘 | `public/callog-icon.png`, `icon-*.png`, `apple-touch-icon.png` | **8단계(사람 결정)**. 지금은 파랑→보라 그라데이션 + 빛나는 파형 |

- 완료 기준
  - 이 명령에서 금색 줄이 사라짐: `grep -n "border-left: *[2-9]px\|::before" src/styles/*.css`
  - 띠 동물(운세·도장) 말고는 화면 문구에 이모지가 없음

### 6단계: 화면 크기가 바뀌어도 같게 (멘토 "휴대폰 화면처럼 전체가 위아래로")

- 할 일
  - 어르신 `--e-zoom`(넓은 화면에서 1.08배)을 없앱니다(`elder.css` 118행 부근, `lib/fontScale.ts` 주석도 정리). 지금은 글자가 390px 폭에서 27px, 820px 이상에서 29.16px입니다.
  - 휴대폰에서 보호자 폼(가입·등록·지병·초대)을 감싼 바깥 테두리 상자를 넓은 화면과 같이 없앱니다(`theme.css` `.app-card`).
  - 안쪽만 스크롤되는 상자가 있으면 없애고 페이지 전체가 스크롤되게 합니다.
- 완료 기준: 360·390·820·1280px에서 같은 요소의 `getComputedStyle(...).fontSize`가 같음.

### 7단계: 보상과 빈 화면 (Duolingo · 토스 결과 화면 원칙)

- 할 일
  - 출석도장: 평소엔 도장 하나 찍히는 정도로 절제합니다. 7칸을 다 채운 날(달토끼 금빛 복주머니)만 크게 축하합니다.
  - 연속이 끊긴 날 문구는 탓하지 않고 "다시 시작해요"처럼 씁니다(`features/attendance/*` 문구만 확인·수정).
  - 운세 결과 등 숫자·이름이 나오면 그게 무슨 뜻인지 한 줄을 붙입니다(토스: '72점'만 보여 주지 말 것).
  - 빈 화면(예: "등록된 어르신이 없습니다")은 이유와 할 일 버튼을 함께 둡니다.
- 완료 기준: 축하 애니메이션은 마일스톤에서만, 빈 화면마다 다음 할 일 버튼이 있음.

### 8단계: 사람이 정할 것 (묻고 멈추기)

1. **"안부 시작하기" 버튼**
   - 지금: 아직 안 답한 날 앱을 열면 바로 첫 질문으로 갑니다(`eInvited.tsx` 64행). 처음 화면의 "안부 시작하기"는 첫 질문에서 "이전"을 눌렀을 때만 보입니다(`eCheck.tsx` 128행 → `/elder/home`).
   - 선택지: (A) 첫 질문에서 "이전"을 숨기고 이 버튼을 없앰 / (B) 그대로 둠
2. **앱 아이콘**: 그라데이션·빛 없는 새 아이콘(단색 바탕 + 글자 또는 단순 기호). 이미지 생성 AI로 만들지 않습니다.
3. **색 변경**: 1~7단계 뒤에도 어둡고 '밤티' 난다는 평이면 기본 바탕을 밝게 바꿀지(기존 "한낮"/"라이트" 테마를 기본으로).

## 4. 확인하는 법

- 실행: `cd demo/v1 && npm install && npm run dev`
  - `.env.local`(Supabase 키)이 없어도 화면은 뜨고 데이터만 비어 있습니다.
  - 어르신 질문 화면은 질문 데이터가 있어야 보이므로 실제 초대 링크로 확인합니다.
  - 개발 중에는 `?preview`를 붙이면 어르신 화면 진입 확인을 건너뜁니다.
- 단계마다 바꾸기 전과 후를 360·390·820·1280px 폭으로 캡처해 사람에게 보여 줍니다(어르신 처음·질문·말하기·완료, 보호자 시작·가입·목록·등록·지병·사용 안내).
- 테마 4종 × 글씨 크기 3단계를 최소 한 화면씩 확인합니다.
- `npx tsc -b`와 `npm run build`가 통과해야 커밋합니다.
- 참고: 말하기 화면의 "(개발용) 테스트 파일 사용" 버튼은 `import.meta.env.DEV`에서만 보이므로 고치지 않아도 됩니다.
